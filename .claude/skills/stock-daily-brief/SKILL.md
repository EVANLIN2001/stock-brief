# 盤後戰報

每天收盤後，把追蹤標的的「價格 + 籌碼 + 技術面 + 消息面」整理成一份可以三分鐘讀完的
HTML 儀表板。目標讀者是自己有部位、想知道今天發生什麼事的人，不是要被推銷買賣建議的人。

這份 skill 的價值在於**把散在四五個網站的東西一次撈齊並交叉對照**：光看股價不知道
是誰在買，光看法人買超不知道技術面位置，光看新聞不知道市場買不買單。

## 兩個場次

| 場次 | 何時跑 | 內容 |
|---|---|---|
| `tw` | 台股 13:30 收盤後，建議 16:00 之後 | 清單裡的台股（2330、5425） |
| `us` | 美股收盤後，即台北時間隔天早上 | 清單裡的美股（MU）＋費半／那指／台積電 ADR |
| `both` | 需要一次看完時 | 兩邊都出 |

判斷場次：使用者明說就照做；沒說的話，用台北時間推斷——下午到晚上通常是要看台股，
早上通常是要看昨晚美股。不確定就問一句，比猜錯整份重做快。

**16:00 之前跑台股會拿到不完整的籌碼**，因為證交所三大法人日報約 15:00 才發布，
個股日成交檔有時甚至隔天才更新。腳本會自己往回找最近有資料的交易日並寫進 warnings，
你要做的是在報告和對話裡誠實講出「這是哪一天的數字」，不要讓使用者以為是今天的。

## 追蹤清單

`assets/watchlist.json`。要增刪標的就改這個檔：上市填 `.TW`、上櫃填 `.TWO`、美股直接填代號。
使用者說「加一檔 XXX」時，直接改檔案再跑，不用重寫腳本。

## 流程

### 1. 抓數據

```bash
cd <skill目錄>
python3 scripts/fetch_tw.py --out /tmp/data_tw.json    # 台股場次
python3 scripts/fetch_us.py --out /tmp/data_us.json    # 美股場次
```

台股會抓證交所／櫃買官方的三大法人與融資融券，加上 Yahoo 一年歷史算技術指標；
美股只有行情與技術面（美股沒有台股那種每日法人公開日報，13F 是季更新，
拿來當日指標會誤導）。

**跑完先看 stdout 的 warnings 再往下走。** 常見狀況：官方檔比 Yahoo 慢一天（腳本會自動
改用 Yahoo 收盤並標註來源）、連假無資料、某個來源逾時。有 warning 不代表要停，
代表報告裡要講清楚。

### 行情來源會自動切換

Yahoo 常對特定 IP 整段回 429（query1／query2 都擋），一掛掉技術指標就全空、美股整個
場次失效，所以每種標的都備了第二條路：

| 標的 | 主要 | 備援 |
|---|---|---|
| 上市（.TW） | Yahoo | 證交所 `STOCK_DAY` 月成交檔，往回撈 13 個月 |
| 上櫃（.TWO） | Yahoo | 櫃買 `tradingStock` 月成交檔，同樣 13 個月 |
| 加權指數 ^TWII | Yahoo | 證交所 `MI_5MINS_HIST` 月歷史 |
| 櫃買指數 ^TWOII | Yahoo | **無**。Yahoo 掛掉時這一列會直接消失，不是 bug |
| 美股個股／ADR | Yahoo | stockanalysis.com |
| 美股指數 ^SOX ^IXIC ^GSPC | Yahoo | 對應 ETF（SOXX／QQQ／SPY）**代理** |

實際用了哪一條會寫進每檔的 `resolved.source`，切換時也會進 warnings。
**報告的來源標註一律照 `resolved.source` 寫，不要因為函式叫 `yahoo_chart` 就寫成 Yahoo。**

美股指數走代理時要特別小心：**SOXX 五百多點、費半六千多點，不是同一個量級**。
腳本已經把 context 的 `name` 改成「費城半導體（SOXX ETF 代理，非指數點位）」，
報告要照這個名稱寫，只引用漲跌百分比，**不要把 ETF 價位當成指數點位講出去**。

### 2. 查消息面

用 `web_search`，每檔 3–5 則。台股用中文查、美股用英文查：

- 台股：`台積電 外資 買超 2026年8月`、`台半 5425 營收`，優先經濟日報、工商時報、
  鉅亨網、MoneyDJ、公司重訊
- 美股：`Micron MU stock news`、`MU analyst price target`，優先 Reuters、Bloomberg、
  CNBC、公司 IR

**別只查個股名。** 真正在推動這三檔的是產業變數——HBM 與 DRAM 合約價、CoWoS 產能、
先進製程報價、AI 資本支出、美元兌台幣、關稅與出口管制。這類新聞放進報告的價值
常常高於「某某外資調升評等」。

摘要一律**用自己的話重寫**，一則兩句以內，附來源名稱、日期、連結。不要整段複製原文，
一方面是著作權，一方面照抄反而比改寫難讀。

### 3. 寫 notes.json

搜尋結果與判讀寫成這個格式（給儀表板吃）：

```json
{
  "headline": "一句話講今天最重要的事",
  "macro": "一到兩句大盤／族群背景",
  "stocks": {
    "2330": {
      "news": [
        {"title": "標題", "summary": "自己改寫的兩句摘要",
         "source": "經濟日報", "date": "2026-08-05", "url": "https://..."}
      ],
      "trend": {
        "stance": "技術面偏多",
        "signals": ["收盤站回月線，20 日乖離轉正 1.6%", "外資單日買超 12,251 張，為近月最大"],
        "support": "2,340（月線）",
        "resistance": "2,510（前高）",
        "analyst": "多家券商 2,600–2,800（2026/07 最新報告）",
        "watch": "外資買超能否連三日"
      }
    }
  }
}
```

`news` 空陣列是可以的，儀表板會顯示「今天沒消息」。`trend` 省略也可以。

### 4. 產出儀表板

```bash
python3 scripts/build_dashboard.py \
  --tw /tmp/data_tw.json --us /tmp/data_us.json --notes /tmp/notes.json \
  --session tw \
  --out "/mnt/user-data/outputs/盤後戰報_20260805_台股.html"
```

只有一個場次就只給 `--tw` 或 `--us`。檔名帶日期與場次，方便日後翻。
產出是完全自足的單檔 HTML——沒有 CDN、沒有外部字型、圖表是伺服器端算好的 inline SVG，
所以離線能開、能轉寄、能封存。

### 5. 交付

用 `present_files` 給檔案，**同時在對話裡寫 3–5 行重點**。使用者常常在手機上先看聊天訊息，
只丟一個檔案連結等於逼他多點一次。重點摘要要包含：今天漲跌、法人方向、
最值得注意的一件事、資料日期（如果不是當天）。

## 趨勢觀察怎麼寫

使用者想知道「未來會怎樣」，而誠實的回答是：沒有人知道。所以這一段寫的是
**現在處在什麼狀態、有哪些訊號、要盯什麼**，不是預測價格。

好的訊號寫法，每一句都掛在資料裡真實存在的數字上：

- ✅「收盤 2,405 站回月線 2,366，20 日乖離由負轉正」
- ✅「外資買超 12,251 張，但融資同步增加 762 張，散戶跟車跡象」
- ✅「RSI 48.8 中性偏弱，KD 在 40 附近黃金交叉」
- ❌「預計下週上看 2,600」— 這是憑空生成的數字
- ❌「建議逢低承接」— 這是投資建議，不是這份報告該做的事
- ❌「技術面轉強」但講不出是哪個指標轉強 — 空話

`stance` 用「技術面偏多／中性／偏空」這種描述當下配置的說法，不要用「看多／看空」，
差別在於前者陳述事實、後者是喊單。

`analyst` 欄位只能放**搜尋到的、有出處的**券商目標價，並註明時間。查不到就留空，
不要自己估一個數字填上去——那是這份報告最容易造成實質傷害的地方。

矛盾訊號要講出來，不要挑好聽的講。價漲但法人賣、技術面偏多但融資暴增、
外資買但自營大賣，這些不一致本身就是資訊。

## 資料新鮮度與休市

- 每份報告的頁首與對話摘要都要出現交易日期
- 遇到週末、國定假日、颱風假：腳本會回傳上一個交易日的資料，這時要在對話裡
  第一句就說「今天休市，以下是 X 月 X 日的資料」
- 台股與美股交易日不同步很正常（美股沒有的台灣連假、反之亦然），
  兩個 `trading_date` 不一樣不是 bug
- 美股夏令時間 04:00 收盤、冬令 05:00（台北時間），早上跑一定拿得到完整收盤

## 常見狀況

**某個資料源掛了** — 其他照出，缺的那塊在報告裡標明缺什麼、為什麼缺。
不要因為缺一塊就整份不做。

**使用者只問一檔** — `--codes 2330` 或 `--symbols MU` 縮範圍，出單檔版本，快很多。

**使用者想看更長期間** — `common.py` 的 `yahoo_chart(rng=...)` 可以改 `2y`、`5y`；
走勢圖固定畫最近 60 個交易日，要改就調 `build_dashboard.py` 裡 `history` 的切片。

**使用者問「該買該賣嗎」** — 給資料、給不同角度、講清楚多空各自的依據，
但不要下買賣結論。可以坦白說這超出這份報告的範圍，決策要看他自己的成本、
部位大小與風險承受度，那些資訊報告裡沒有。

## 排程

這份 skill 不會自己定時跑。要每天自動出，在 Claude 建兩個排程任務：

- 台北時間週一至週五 16:00 →「跑今天的台股盤後戰報」
- 台北時間週二至週六 07:00 →「跑昨晚的美股盤後戰報」

（美股排週二到週六，因為對應的是週一到週五的美股交易日。）

## 檔案

```
stock-daily-brief/
├── SKILL.md
├── assets/watchlist.json      追蹤清單，可直接編輯
└── scripts/
    ├── common.py              HTTP、Yahoo 行情、技術指標
    ├── fetch_tw.py            台股：證交所／櫃買官方籌碼 + 技術面
    ├── fetch_us.py            美股：行情 + 技術面 + 大盤對照
    └── build_dashboard.py     渲染單檔 HTML
```

技術指標為收盤價自行計算：MA5/10/20/60、RSI 14（Wilder）、KD(9,3,3)、
MACD(12,26,9)、20 日乖離、52 週高低、量能比。全部標準函式庫實作，不依賴 pandas。
